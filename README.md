# adb + OpenCV 安卓自动化

用 Python 控制安卓手机：截图 → 识别 → 点击。

## 核心原理

```
adb 截图  →  OpenCV 找图（返回坐标）  →  判断相似度  →  adb 点击  →  循环
```

## 踩过的坑（都是真金白银）

### 环境类

- **Google 源被墙** → 用腾讯镜像 `mirrors.cloud.tencent.com/AndroidSDK/` 下 adb
- **Python 3.14 当时装不上 OpenCV**（2026-09）→ 一度另建 Python 3.12 的 conda 环境。
  后来 OpenCV 5.0.0 出了 3.14 的轮子，现在直接用项目内的 `.venv`（Python 3.14.6）。
- **`cv2.imread` 读不了中文绝对路径** → 用 `os.chdir(ROOT)` 切到项目目录，改用相对路径
- **相对路径找不到文件** → 脚本开头统一 `os.chdir(ROOT)`，在哪运行都对
- **用 bash 的 `>` 重定向存截图会写坏文件**（终端里 `adb ... > x.png`）。
  bash 会把二进制里的 `\n` 换成 `\r\n`，同一张图体积从 20KB 涨到 5.3MB。
  → **截图一律用 Python 的 `open(path, "wb")` 存。**

### 自动化思维类（更重要）

- **命令没报错 ≠ 命令生效了**。adb 的 input 命令失败时经常静默无声。
  → 每次操作后截图对比，验证结果。

- **手机偶尔会丢弃 input 命令**，尤其是刚连接后的头几次。
  → 加预热，不达标就重试。

- **"画面没变"不等于"命令失败"**。列表已经滑到底了也不会变。
  → 校验只能告诉你「有没有变」，判断原因得靠人看截图。

- **`matchTemplate` 永远会返回一个"最像的"结果**，哪怕只有三分像，
  它也绝不说"我没找到"。
  → **必须设相似度阈值**（0.8）。点错地方比什么都不点危险得多。

- **截图前要确保回到了目标界面**。Home 键被丢弃时，截到的是上一个界面，
  后面所有判断全错。
  → 回桌面 → 截图 → 检查分数 → 不够高就重来。

- **一次截图要花 2 秒，但画面是「命令刚开始」那一刻就拍下的**，
  剩下的时间全在压缩和传输。
  → 所以 `sleep` 该等还得等，别指望截图耗时替你等。删掉 `sleep(1.5)` 实测会拍到
  动画中途的画面（与静止桌面差异 68~84，保留 sleep 时是 0.02）。

- **失败可能一声不吭**。`tap 9999 9999`（越界坐标）实测：
  `returncode=0`、`stderr` 全空、**屏幕上什么都没发生**。
  → 只看返回值判断成败是不够的，必须验证**实际结果**。

- **验证指标选错，结论就全错**。用「平均亮度」分不出「动画中途」和「已稳定」
  （119 vs 130 混在噪声里）；换成「与静止桌面逐像素对比」立刻现原形。
  → 挑指标时先问：这个数字**真的**能区分我想区分的两种情况吗？

- **没执行过的代码 = 没写过的代码**。重试分支写完后一直没被跑到过，
  直到把 `THRESHOLD` 设成 2.0（谁都不可能及格）才第一次验证它。
  → 写完分支，必须想办法**逼它执行一次**。

- **设计「失败测试」前，先证明这个输入真的不可能匹配**。
  曾经拿 `template[:50,:50]` 当"假模板"，结果它跟图标原位**一模一样**，
  相似度 1.000 —— 白测一场，还差点冤枉了脚本。

- **`range(1, 3)` 只跑 2 次**，含头不含尾。它不报错，只是默默少做一次。

- **手机 offline 时 `screencap` 一个字节都不吐** → 写出 0 字节的文件 →
  `cv2.imread` 对此**静默返回 `None`**，错误一路拖到几百行外的 `matchTemplate` 才炸，
  报的还是一句跟掉线毫无关系的 `type == _templ.type()`。
  → **截图后立刻检查 `img is None`，在源头报错**；恢复用 `adb reconnect`。

- **匹配数 ≠ 目标数**。同一个图标在屏幕上出现 6 次，`np.where(scores >= 0.8)` 捞出 18 处 ——
  滑动窗口挪 1 像素画面几乎没变，相邻位置分数照样很高（0.848 / 1.000 / 0.848）。
  → 要「最靠上那个」就取 `ys.argmin()`，别把匹配数当成卡片数。

- **能确定的那一步只做一次，别「退到对为止」**。找不到列表时按一次返回是**有把握**的
  （从视频页退一步必然回到列表页）；而「一直退到看见为止」一旦判定出错，
  会一路退出课程、退回桌面。→ 修的时候只做你能确定的那一步。

## 三条铁律

1. **验证** —— 每步操作后检查结果，别假设成功
2. **重试** —— 单次失败很正常，给 2~3 次机会
3. **达标才动手** —— 分数不够就不点，宁可卡住也不乱点
